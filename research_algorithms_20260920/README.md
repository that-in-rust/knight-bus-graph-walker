## Research Method

1. Establish the ordinary competent algorithm and closest specialized prior art.
2. Look for state or work elimination, rather than simply moving the same data to SSD.
3. Specify an exact supported operator before deriving an optimization.
4. Write a correctness invariant or error theorem and identify adversarial counterexamples.
5. Calculate end-to-end RAM, read/write volume, disk retention and unavoidable output costs.
6. Test algebra and failure cases with small independent computational probes where useful. These are not production benchmarks or formal proofs.
7. Separate existing foundations, an inherited repository mechanism and the proposed new delta.
8. Seek an independent challenge before describing any candidate as ready for implementation or submission.

Expert lenses: graph algorithms, numerical linear algebra, external-memory systems, user-workflow value and skeptical prior-art review. These are review perspectives, not personal endorsements or evidence of correctness.

The conventional approach is compressed adjacency plus bounded external execution. Three alternative directions guide the search: sufficient-statistic elimination from linear algebra; proof-carrying selective work from incremental computation; and replay/checkpoint tradeoffs from time-space complexity. Each must justify its transfer, not merely acquire a new name.
