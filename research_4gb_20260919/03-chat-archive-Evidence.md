## Substantive Corrections

1. **Do not resurrect the naive incumbent.** The archive itself names packed/compressed adjacency, primitive message arrays, compressed Node2Vec walks, compact KNN lists, topK/topN structures, memory trees and job control. Its strongest conclusion is to measure a better constrained execution policy against these features, not against imaginary all-pointer GDS storage. The earlier feasibility artifact's direct compressed-adjacency/Pregel reads and the PRD04 artifact's direct guard read remain independent primary checks of this central correction.
2. **An exact estimator is not a hard bound or a completed job.** Huge fixture dimensions exercise estimate arithmetic without allocating their graphs. A guard before compute can still occur after graph loading; its estimate can omit a path or use an optimistic range. Admission must include acquisition/build/export/refresh, reject unsupported estimate paths in strict mode, and use aggregate physical accounting. A run receipt proves what was observed under that run's instrumentation, not a universal algorithm theorem.
3. **Configured changes are not automatically transparent optimizations.** Lower GraphSAGE sample sizes change sampled computation; changing training batch size can change optimizer trajectories. Warm-start Louvain/Leiden or PageRank can change finite-run results. Count-visits output is not the full random-walk corpus. Compact binary HashGNN output is not the same API as dense vectors. Each may be a useful product, with a separately named oracle and loss/compatibility contract.
4. **Preserve output and stopping semantics.** Reached sets, traversal order, paths and distance-only outputs are different. Pin tie rules and concurrency only where the public contract promises them; exact reproduction of an internal scheduler is not a universal prerequisite for mathematical correctness. KNN pair counters differ from update counts. Reducing messages requires the relevant algebra and a numerical policy; reassociation can affect tolerance crossings. Cancellation, max-iteration exit and convergence remain separate outcomes.
5. **A support registry is neither code nor proof of absence.** The WCC Rust-literal search was corrected by the TSV loader. Conversely, eight registered names do not prove any dispatcher, topology or side-effect behavior. A generic fixture with more counted than materialized relationships is a negative completeness test, not a positive algorithm oracle. These are historical source-state observations, not a fresh audit of today's implementation.
6. **Novelty is narrower after this read.** Completed epochs, spill profiles, heavy-node separation, compact internal state, output-window materialization, incremental maintenance, receipt-based admission and lifecycle control already appear in this archive. H1's bucket-before-full-index first-answer hypothesis may still deserve comparison, but sealed epochs/manifests are not its new mechanism. H2/lead row-mass quotients retain the classical-prior-art status recorded in PRD04. H3 remains a refinement of existing exact blocking/pruning, not a whole-corpus invention. New value must be a specific legal schedule with a demonstrated lifecycle improvement, not a new name for these parts.

## Numerical Counterexample

Archive lines 3343-3358 infer that missing-weight fallback `threshold + 1` always passes a strict threshold. Fresh primary source reads at clean pinned GDS commit `dc4417b3c1feffbdf9eb6293fbbd1ffb1b7233b9` consumed these whole files, relative to `gitrefrepo/Neo4j family/neo4j-gds-src/`:

| --- | --- | --- |
| `algo/src/main/java/org/neo4j/gds/wcc/Wcc.java` | 1-144 | Lines 137-139 return a double-valued `threshold + 1`; 100-130 allocate DSS and choose strategy. |
| `algo/src/main/java/org/neo4j/gds/wcc/UnsampledStrategy.java` | 1-171 | Lines 159-166 pass the fallback into traversal and union only if the supplied property is strictly greater than threshold. |
| `procedures/facade-api/configs/community-configs/src/main/java/org/neo4j/gds/wcc/WccBaseConfig.java` | 1-47 | Lines 36-40 check that a positive threshold has a weight-property name; this method does not impose a small finite numerical bound. Other front-door validation was not exhaustively traced. |

Java double has 53 significant binary bits and arithmetic uses round-to-nearest, ties-to-even. At `t = 2^53 = 9007199254740992`, the next representable value above t is t+2, so `t+1` rounds to t and the strict predicate fails. This is a derivation from the [Java numeric representation](https://docs.oracle.com/javase/specs/jls/se21/html/jls-4.html#jls-4.2.3) and [floating arithmetic rules](https://docs.oracle.com/javase/specs/jls/se21/html/jls-15.html#jls-15.4), specifically the numeric table and rounding-policy paragraphs, not a full specification read.

A read-only JavaScript binary64 arithmetic check returned `[9007199254740992, 9007199254740992, 9007199254740994]` for `[t,t+1,t+2]`, and false for `(t+1)>t`. No Java/GDS procedure or graph test was run. This refutes the unconditional arithmetic inference; whether a particular projection supplies that fallback through the entire public procedure remains a proposed integration test. Do not silently replace it with `nextUp(t)` in a compatibility profile: that could change the pinned behavior. Test representative finite thresholds, equality, large thresholds, defaults and any admitted non-finite values explicitly.

## Lifecycle Model Addendum

Use the complete parameterized model in `03-feasibility-Evidence.md` and the quotient construction/reconstruction/refresh model in `03-prd04-verification-Evidence.md`. The archive adds stronger evidence for the following mandatory checks, not a replacement denominator or a new measured model.

| Phase | Required accounting and falsifier |
| --- | --- |
| Acquisition and import | Decode buffers, maximum record size, external-ID remapping, type/property validation, sort runs, source staging and durable truth all precede the algorithm guard. A late malformed record or late edge can invalidate an early purported final answer. A remote extractor is an explicit dependency, not free standalone capacity. |
| Prepared artifact | Require all retained prepared extents plus topology, dictionaries, properties, selected reverse/index structures, quotient/shared rows and persisted results within 50,000,000,000 bytes. This is persisted disk, not the old projected-GDS-RAM scenario. Declare total working disk separately, including unpublished build runs and recovery orphans. |
| Query execution | Fit actual overlapping runtime, metadata, state, codec/I/O buffers, output, charged cache/kernel state and guard within `4e9 - O`; O=1e9 is only a provisional OS reserve. Charge task count and per-task state, not just thread count. A sampled small-graph high-water mark is not a worst-case bound. |
| First complete answer | Include acquisition, validation, ID mapping, build, publication, cold query, full decoding/export and required verification. First row, first progress event or first receipt is not completion. Failed/refused/deadline-exceeded/nonconverged runs remain distinct from completed answers. |
| Export and verification | Bound all producer, server, driver and sink buffers together. Count route length, walk count, vector width, output IDs, duplicate rows and any external canonicalization sort. A slow consumer pins results, source generations and possibly tasks. Backpressure can make the run safe yet indefinitely unfinished. |
| Refresh and recovery | Charge old reader-pinned generations plus the new generation, WAL/deltas, sort/aggregation scratch, shared-extent metadata and concurrent query/export state. Measure update arrival versus sustainable service, first refreshed answer and cleanup after failure. Repeated small changes can require global quotient refinement or large coarsened-graph rebuilds. |

Illustrative arithmetic, not measured results: at V=200 million, three f64 PageRank arrays alone use `24V = 4.8GB`; a baseline DSS with one 64-bit parent per vertex uses `8V = 1.6GB` before paging overhead and other state, while two such seeded lanes use 3.2GB. These are selected representation subtotals, not universal lower bounds. One 128-dimensional f32 result matrix uses `4*128V = 102.4GB` and therefore cannot be retained under the 50GB artifact cap without changing representation or destination policy. Windowed export reduces live RAM, not those total bytes. Three such dense FastRP matrices would be 307.2GB of raw matrix storage if all persisted uncompressed.
