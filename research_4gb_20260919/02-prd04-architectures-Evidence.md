### Restricted Exact Contract

The following is mathematical reasoning and an unimplemented format/kernel hypothesis, not a measured result. Shared-neighbor one-mode projection is established precedent: the official [NetworkX projected_graph documentation](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.bipartite.projection.projected_graph.html) defines that adjacency and distinguishes simple from per-shared-neighbor multigraph projection. This is a precedent check, not an exhaustive hypergraph literature review.

Let n entities, k eligible attributes and h unique eligible incidences define binary matrix B at one immutable generation. Define A[i,j]=1 exactly when i!=j and entities i,j share an eligible attribute. Explicitly clear the diagonal of sign(BB^T): subtracting I alone produces -1 for an isolated entity with an empty incidence row. Preserve isolated entities separately from the incidence stream.

For this undirected, unweighted, simple derived graph, entity-to-entity distance in the bipartite incidence graph is twice the distance in A. Every projected edge lifts to a two-hop incidence walk via a shared attribute; every even incidence walk projects to an entity walk. Taking minima in both directions gives equality, including unreachable pairs. This establishes reached-set and distance equivalence, not identical enumeration of all paths, path multiplicities or canonical parents.

An entity-level FIFO BFS processes entities in nondecreasing distance. When an attribute is first encountered from distance d, mark it visited and scan its entire eligible posting, discovering unseen entities at d+1. No later entity can encounter that attribute at a smaller distance. Therefore later expansions of that posting cannot improve any distance and may be skipped. Mark entities on discovery; expand each reached entity row once and each reached attribute posting once. Store `(parent entity, witness attribute)` at first entity discovery, with the source marked separately. The result is one valid shortest witness path, not every shortest predecessor or every witness attribute. Tie-breaking must be declared if parity demands more than distance/validity.

WCC needs even less: for each nonempty attribute posting, union its first entity with every other member. Each factor's star connects exactly the entities of its clique; the union of those stars preserves components across factors. This star is valid for WCC ONLY, not a replacement adjacency for BFS distances: two noncentral members of one factor are one projected hop apart but two star edges apart. A component denotes connectivity under this rule, not one true identity, collusion, culpability or fraud.

Eligibility must be representable as fixed entity/attribute/incidence filtering at the same generation. Arbitrary pair-dependent conditions, deny/path policies, time-respecting paths, similarity thresholds requiring multiple shared attributes, weight aggregation, directed projections and requested multiedge multiplicities need different proofs or explicit fallback. Query-time degree thresholds also require the correct generation/filter scope. A single shared attribute can connect a large benign population; dropping it for performance changes semantics unless eligibility already excludes it. Visited attributes are per traversal, not globally reusable across independent sources/queries. Multi-source nearest-seed BFS is a different result from independent BFS for every seed.

### Build And Runtime Accounting

Let f[a] be attribute posting length. Pair generation before dedup can produce S=sum_a f[a]*(f[a]-1)/2 records; distinct projected edges mA<=S. One factor of size f already induces f*(f-1)/2 edges. Factor-native construction avoids S entirely, rather than merely moving the pair join from query to build. It still pays for extracting/validating every raw membership, stable-ID joins, dedup, sorting and publication.

### Other Algorithm Families

Incidence is not a universal drop-in representation of the simple projected adjacency operator. `B*(B^T*x)` counts shared attributes and includes diagonal contributions, whereas A uses Boolean existence and a zero diagonal. Alternating normalized entity/attribute propagation also generally differs from PageRank on A. For weights deliberately defined by common-attribute multiplicity, some products can be factored with correct diagonal/degree treatment, but that is a different declared operator.

Exact triangle count cannot simply sum choose(f[a],3): overlapping factors double-count triangles, and three pairwise factors can form a triangle with no single common factor. Similarity on B rows retains the intended incidence sets but still needs complete candidates, exact threshold/top-k/tie rules and can have quadratic output. Louvain/Leiden on an incidence graph or star is not the same modularity problem as on the projected clique; degree/edge multiplicity and refinement matter. FastRP can use factor products only when they implement its exact declared propagation operator; normalization, self influence and duplicate-shared-attribute weights prevent blindly reusing this BFS proof. These are separate algorithm contracts, not an argument to discard incidence's WCC/BFS build advantage.
