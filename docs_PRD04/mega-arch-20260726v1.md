## 1. How the architecture actually evolved

The corpus reads as a single argument that changed its mind four times. The
shape of that argument is more useful than any one document.

```text
  v001/v002        "immutable dual CSR + mmap beats record chains"
   docs/           -> MEASURED: 4.5-78.9x lower RSS on fixed-hop traversal
                     (1MB / 50MB / 2GB corpora). Still the only measured win.
        |
        v
  ATLAS            "every algorithm wants its own byte shape"
   docs/           -> 60 algorithms -> 13 layout families
        |
        v
  PRD02            "13 durable layouts is disk/build/invalidation suicide"
                   -> collapse to 3: topology + property planes + scratch/sidecar
        |
        v
  PRD03            "check that against real GDS source"
                   -> PageRank/BFS/WCC fit flat CSR + sidecars.
                      NodeSimilarity is the family that breaks it.
        |
        v
  PRD04 Arch01-06  "compose bytes-layers with runtime-layers"
                   -> A(flat) + B(tiles) + C(budget) + D(manifest) + E(algebra)
                   -> GRAIN: strata + manifest-as-estimator
                   -> Arch06: THE SCRATCH IS THE OTHER HALF OF RAM
        |
        v
  PRD05            "price it honestly"
                   -> 17 adversarial ducks. Strict-RAM PageRank is 1.5-5x SLOWER.
                      "Lower RAM" names two OPPOSITE mechanisms.
        |
        v
  PRD06            "the harness is the product; code is regenerable"
        |
        v
  A01 PART 0       "materialize per algorithm, on demand"   <- CURRENT
   (2026-07-26)    -> the format debate dissolves
```

**The single most important correction in the whole corpus** (PRD05 Correction 6):

```text
  There are TWO ways to reduce resident memory, and they have OPPOSITE
  latency effects:

  1. REPRESENT FEWER BYTES  -> remove duplicate orientations, narrow IDs,
                               compact state, better locality, fewer copies
                            -> reduces RAM *and* latency

  2. EXTERNALIZE BYTES      -> leave topology on NVMe, stream/fault/spill
                            -> reduces RAM, INCREASES latency

  Any claim of "lower RAM and faster" SHALL identify which bytes were
  ELIMINATED rather than merely MOVED.
```

Every RAM pattern in §4 is tagged with which mechanism it uses.

## 2. The current architecture

### 2.1 The three planes (invariant since `prd-l1`, survives every revision)

```text
   OLTP truth                    Neo4j-shaped, or delegated (CozoDB-class)
        |                        under the OLAP-only scope
        | committed facts / receipts / backup
        v
   PROJECTION BUILD STORE        canonical analytical IR. NEVER queried by users.
        |                        Exists so extraction happens EXACTLY ONCE.
        | materialize on demand
        v
   PER-ALGORITHM ARTIFACTS       one sealed artifact per algorithm run
        |                        immutable, generation-sealed, atomically published
        v
   OLAP answers, exact as of watermark W
```

### 2.2 The current decision — per-algorithm materialization (A01 PART 0)

GRAIN's five rules, unbundled — only two were expensive, and they are the two
that do not help the priority families:

| Rule | What | Cost | Verdict |
| --- | --- | --- | --- |
| G1 | degree-ranked dense IDs | a build-time sort | **KEEP** — triangle counting wants it anyway |
| G2 | three strata / three codecs (flat, Elias-Fano, 2D blocks) | 3 encodings, 3 debuggers | **DROP** |
| G3 | **manifest is the estimator** | layout-agnostic | **KEEP** — the only unclaimed differentiator |
| G4 | blocks as spill unit | requires G2 | **DROP** |
| G5 | immutable generations | a directory + atomic rename | **KEEP** |

**G3 does not depend on G2.** Per-algorithm artifacts make the estimator *exact*
rather than a fitted polynomial — which retires `Arch05` X1, the corpus's own
self-declared *"load-bearing"* unproven bet.

### 2.3 The deployment topology (A01 PART 1B)

```text
  +-------------------------------------+     +---------------------------+
  |  PRODUCTION NEO4J (stock)           |     |   OLAP BOX (ours)         |
  |  grain-export.jar  <- TINY          |     |  full Rust OLAP runtime   |
  |   extraction ONLY, no algorithms    |---->|  Build Store              |
  |   throttled, resumable              |     |  per-algorithm artifacts  |
  |   -- or skip: read the BACKUP       |     |  admission + receipts     |
  +-------------------------------------+     +---------------------------+

  in-process = the ADOPTION PATH (one line, uncontested ground)
  separate   = the RUNTIME (no page-cache eviction, no IOPS war)
```

### 3.5 The build order the atlas recommends

```text
  P0  1. anchor_dual_csr        Degree/BFS/DFS/RandomWalk -- closest to v002 proof
      2. iterative_rank_vector  PageRank first, then ArticleRank/Eigenvector/HITS
      3. connectivity_lowlink   WCC + SCC are the high-value baseline analytics
      4. relaxation_frontier    Dijkstra ST, then SS, then A*, then delta-stepping
      5. ordered_wedge          Triangle Count -> Node Similarity

  P1  partition_refinement (Louvain, Label Prop), edge_order_forest, peel_bucket
  P2  flow_residual, dag_order, embedding_training (FastRP only)
  P3  DOWNGRADE: feature_metric (K-Means/HDBSCAN ignore relationships),
                 training-heavy embeddings, CELF, APSP
```

**Five formats to prototype if only five are built:** DegreeCentrality-AnchorDualCsr,
Bfs-TraversalFrontier, PageRank-InboundPower, Dijkstra-HeapRelaxation,
TriangleCount-OrderedWedge.

### 3.6 The split that decides the architecture (Arch02 R2)

```text
  SCAN PROBLEMS  = "read all edges, repeatedly"  -> LAYOUT solves them
      WCC 20% | PageRank 15% | paths 10% | FastRP 8% | triangles 5%

  STATE PROBLEMS = "scratch memory explodes"     -> ONLY admission+spill solves them
      Louvain 15% | NodeSimilarity 12%           = 27% of adoption weight

  "No static layout of the ORIGINAL graph removes that cost."
```

**This is why per-algorithm formats are sufficient and GRAIN's strata were not
necessary:** the families that break the budget are broken by *state*, and state
is orthogonal to byte layout.

## 4. The RAM-saving pattern catalogue

Every pattern found across all six folders, organised by **what it attacks**, and
tagged **[ELIMINATE]** (removes bytes → also faster) or **[EXTERNALIZE]**
(moves bytes → usually slower) per PRD05 Correction 6.

### 4.A Attacking GRAPH bytes (layout and encoding)

| # | Pattern | Effect | Mech | Source |
| --- | --- | --- | --- | --- |
| A1 | **Dense u32 node IDs** (vs 64-bit pointers) | 4 B/peer vs Neo4j's 34 B relationship record | **ELIMINATE** | PRD02, ATLAS |
| A2 | **Flat CSR** — `offsets[v]..offsets[v+1]` | replaces pointer-chase; `4E + 8(V+1)` = **5.22 GiB** at 200M/1B | **ELIMINATE** | v002, graph-learning #7 |
| A3 | **Single orientation when the algorithm allows** | dual CSR is 15.65–18.63 GiB; one orientation is 5.22 GiB — **3×** | **ELIMINATE** | PRD05 Duck 5 |
| A4 | **Degree-ranked dense IDs (G1)** | monotone degree array compresses to ~nothing; prefix `[0,k)` = k heaviest; standard triangle optimisation | **ELIMINATE** | Arch05 G1, Terrace |
| A5 | Elias-Fano compressed adjacency | ~1.55× smaller than CSR, random-access without full decode | ELIMINATE | Arch05 G2 — **dropped** |
| A6 | WebGraph-class gap/ζ coding | ~3 bits/link on *web-like* graphs only | ELIMINATE | Arch05 R4 — **rejected as lead** |
| A7 | **Columnar typed property planes** | map only `weight.f32` — never decode Neo4j's 41 B property records | **ELIMINATE** | PRD02 `MmapColumnarPropertyPlaneV1` |
| A8 | Recursive graph bisection reordering | neighbours get nearby IDs → cache lines + smaller gaps | ELIMINATE | Arch06 L3.c |
| A9 | 2D edge blocks (GridGraph) | streamable, skippable | EXTERNALIZE | Arch05 G4 — **dropped** |
| A10 | Posting-block compression / FOR+delta | block-wise integer compression | ELIMINATE | graph-learning #17 (lucene, tantivy) |
| A11 | Roaring bitmap ID sets | per-chunk container choice; huge win on sparse/dense ID sets | ELIMINATE | graph-learning #3 |
| A12 | FST term dictionary | shared-prefix key storage | ELIMINATE | graph-learning #19 |

### 4.B Attacking SCRATCH bytes — *the half Arch01–05 missed*

> `Arch06`'s opening finding: **`RAM = GRAPH BYTES + SCRATCH STATE`**, and for the
> two families that OOM in the wild, **scratch is the killer**.
> *NodeSim on LDBC100: graph ~ a few GB, candidate-pair scratch ~ 100+ GB.*

| # | Pattern | Effect | Mech | Source |
| --- | --- | --- | --- | --- |
| B1 | **Frontier as bitmap, not queue** | 1 bit/vertex vs 32 bits/entry — **32×**. 1B verts: 4 GB → 125 MB | **ELIMINATE** | Arch06 L1.a (Ligra) |
| B2 | **Quantized numeric state** | PageRank f64→f32 = 2× (4.47→2.235 GiB at 200M). Embeddings f32→int8 = **4×** | **ELIMINATE** | Arch06 L1.b |
| B3 | **Sketched state — the NodeSim rescue** | MinHash/HyperLogLog: `O(Σdeg²)` → **`O(V × 256 B)` bounded** | **ELIMINATE** | Arch06 L1.c |
| B4 | **Strata applied to STATE** | hot vertices resident, cold tail spillable — same `ranks.dense`, second dividend | EXTERNALIZE | Arch06 L1.d |
| B5 | **Bounded top-K heaps + `topK`/`topN` caps** | turns NodeSim's quadratic output into a bounded artifact | **ELIMINATE** | Batch-07 B07-004 |
| B6 | **Capped tally maps (Louvain)** | bounds the per-level community accumulators | ELIMINATE (approx) | Arch06 worked ex. 2 |
| B7 | **Levels as tiny generations (Louvain)** | each coarsened level is a small new artifact, not a retained copy | ELIMINATE | Arch05, Arch06 |
| B8 | **Budgeted external sort + k-way merge** | 64 MiB logical budget, ¼ spill buffer — **already in this repo** | EXTERNALIZE | Current-Codebase-Low-RAM-Patterns |
| B9 | **Result sidecars, never base mutation** | outputs don't duplicate or dirty the topology | ELIMINATE | ATLAS, PRD02 |
| B10 | u32 parent array for WCC | 0.745 GiB at 200M vs GDS's atomic `long` 1.49 GiB — **2×** | **ELIMINATE** | PRD05 |

| # | Pattern | Effect | Mech | Source |
| --- | --- | --- | --- | --- |
| C1 | **Semi-external: `RAM = O(V)` by construction** | `\|E\|/\|V\|` is 10–50×, so vertex state on a 50 GB graph is often < 1 GB. **A guarantee, not a prediction** | EXTERNALIZE | **Arch06 L2** — the strongest single idea |

### 4.E Attacking CONSTANT FACTORS (why Rust specifically)

| # | Pattern | Effect | Source |
| --- | --- | --- | --- |
| E1 | **Zero-copy mmap → `&[Edge]`** | the file *is* the runtime structure; no deserialization, no heap copy | Arch06 L4.a (POC-proven) |
| E2 | **Monomorphized kernels** | semiring generics with no vtable, no boxing — algebra flexibility at zero runtime cost. JVM pays object headers + GC for the same abstraction | Arch06 L4.b |
| E3 | **SIMD decode / rank-select / dot products** | compressed strata read at near-flat-CSR speed | Arch06 L4.c |
| E4 | **`io_uring` prefetch pipeline** | keeps 2–3 blocks ahead; disk ~free if compute-bound. **0–5% on resident kernels** — PRD05 Duck 3 | Arch06 L4.d; PRD05 |
| E5 | **ONE budgeted arena, reused across jobs** | `allocated bytes == receipt bytes`, byte for byte. **Honesty becomes mechanically enforced, not audited** | Arch06 L4.e |
| E6 | **No GC, no JVM heap headroom** | JVM practice needs ~1.5–2× estimated bytes of GC headroom that Rust does not | Arch06 closing |

| E8 | **jemalloc background purge** | RSS falls back toward idle after bursts instead of staying pinned | Slater README (competitor practice) |

## 5. The quantitative floors (PRD05 — do not argue with these)

```text
  TOPOLOGY at V=200M nodes, E=1B directed relationships
    dual CSR + keys + index  = 8E + 36V + 16 + K  = 15.65-18.63 GiB
    single orientation       = 4E + 8(V+1)        =  5.22 GiB

  ALGORITHM STATE at 200M nodes
    one u32[V]        0.745 GiB      three f32[V]    2.235 GiB
    one u64/f64[V]    1.490 GiB      three f64[V]    4.470 GiB
    one bitset        0.023 GiB      seven 8B arrays 10.431 GiB  <- Louvain

  WHAT FITS 8 GiB
    WCC        0.745 GiB state + streamed topology     -> COMFORTABLY
    PageRank   2.235 GiB (f32) + streamed topology     -> YES
               one orientation + three f64 = 9.69 GiB  -> NO (must stream/quantize)
    Louvain    >10.4 GiB before maps/subgraphs         -> REJECT or spill
    NodeSim    unbounded candidate pairs               -> REJECT unless sketched/capped
    FastRP     dim x nodes dominates                   -> REJECT/partition/quantize

  THE HONEST SPEED TRUTH
    strict-RAM PageRank = 1.5-5.0x SLOWER than tuned resident GDS.
    20 iterations x 5.22 GiB = 104.4 GiB of topology traffic per run.
      at 50 GiB/s DRAM -> >= 2.1 s      at 5 GiB/s NVMe -> >= 20.9 s
    Externalization is a CAPACITY mechanism, never a speed mechanism.

  DISK
    total vs Neo4j-only: 2-5x (Scenario B), ~2x per additional retained artifact
    wear: NON-ISSUE. Reads dominate; ~20 TB/yr written vs NVMe rated in PB.
```

## 6. What is decided, and what is still open

### Decided

```text
  [x] Three planes: OLTP truth -> Build Store (never queried) -> sealed artifacts
  [x] Per-algorithm materialization on demand; NOT one universal format
  [x] Keep G1 (degree-ranked IDs), G3 (estimator), G5 (generations)
  [x] Drop G2 (Elias-Fano strata) and G4 (2D blocks)
  [x] Admission control + spill is MANDATORY, not optional -- it is the only
      thing that serves Louvain + NodeSimilarity (27% of adoption weight)
  [x] Scratch is half of RAM; L1 patterns are as important as any layout
  [x] Semi-external (RAM = O(V)) is the strongest guarantee available
  [x] Extraction ONCE, in-process, throttled/resumable -- or from the backup
```

## 7. The one-page summary

```text
  STORAGE       flat, dense-u32, degree-ranked, immutable, generation-sealed,
                materialized PER ALGORITHM on demand from a Build Store that
                users never query.

  RESIDENCY     O(V) state resident by construction; edges streamed.
                mmap for speed, O_DIRECT for strict guarantees.

  SCRATCH       bitmap frontiers, quantized vectors, sketched candidates,
                capped tallies, bounded top-K, budgeted external sort.
                THIS IS HALF OF RAM AND ARCH01-05 MISSED IT.

  WORK          push/pull switching, delta convergence, converged-block skip,
                warm start from the last generation, memoized sidecars.

  POLICY        estimate from ~1 KB before reading a byte; admit, spill,
                or REJECT with a printed bill covering RAM *and* disk.
                One arena: allocated bytes == receipt bytes.

  PROOF         parity by one diff; OLTP p99 flat; estimate within +/-15%.

  THE TRAP      "lower RAM" names two opposite mechanisms. ELIMINATING bytes
                is faster. EXTERNALIZING bytes is slower. Never conflate them
                in a claim.
```
