Date: 2026-06-24

is not a generic tour of Neo4j GDS. It records the GDS source facts that should
shape Knight Bus v003 architecture decisions around public surface, named graph
projection, cataloging, memory estimation, algorithms, model/pipeline artifacts,
mutate/write behavior, and compatibility tests.

## PRD Wording Guardrails

- Do not say "CSR support" when the claim means "GDS support." GDS support needs catalog, projection config, schema, labels, relationship types, orientation, aggregation, inverse indexes, properties, memory estimates, result stores, and model/pipeline artifacts.
- Do not say "strict RAM" for a procedure that can throw `MemoryEstimationNotImplementedException`, returns an empty estimate, bypasses validation, or lacks result/model/write-back artifact accounting.
- Do not let Projection Build Store become a serving graph. GDS source is useful as a semantic model for building graph stores, but v003 still needs immutable snapshot publication and generation manifests.
- Do not treat write/mutate as one thing. Mutate updates the named graph/artifact plane; write persists into Neo4j/OLTP-visible storage.
- Do not use docs-only examples as implementation proof. Use them as behavior oracles and back implementation claims with source/tests.
