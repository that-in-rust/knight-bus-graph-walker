## Lead Candidate2 Critique

The lead's corrected identical-normalized-row class-mass recurrence is different from equal-member-rank compression. For a fixed linear PageRank operator, summing contributions to target classes gives a closed class recurrence, while individual vertex scores are reconstructed from the preceding class masses and individual teleport terms. Equal source rows do not imply equal incoming scores: the supplied `0->2, 1->2, 2->0` counterexample prevents division of class mass by class size. This lane's earlier H2 used the stronger incoming-equitability condition; that partition would reject merging 0 and 1 in this example.

The lead reports 512 three-node graphs over 20 iterations with small floating differences; that is attributed evidence, not a rerun here, not a speed measurement and not a GDS parity test. Reassociation can still change a threshold boundary. Account for constructing exact row classes, collision verification, class-to-class coefficients, V-to-class membership, retained original shared rows for reconstruction, personalized teleport/dangling distributions, and V-row output. If the quotient is dense or classes split after updates, reduced iterative state can lose on disk/build/refresh costs. These dependencies belong inside the 4GB/50GB model.

Possible further hypothesis, not established compatibility: for GDS-style nonnegative delta propagation, keep per-row-class emitted mass `s_g(t)`. Reconstruct each destination delta in bounded tiles as `delta_v(t+1)=d*sum_g P_g(v)*s_g(t)`, apply the per-vertex tolerance, then sum surviving deltas into the next source-class mass. Accumulated class emissions could permit final rank reconstruction without a V-sized resident rank array. This is nonlinear thresholded aggregation, not the lead's simple fixed matrix quotient. It still processes individual destinations and needs shared-row/destination-tile build costs, tile accumulator I/O, class-state residency, zero-message handling, initial-step exceptions, vote/reactivation/global stopping audit, numerical policy, export and refresh accounting. No claim of full GDS semantics or new global prior art is made; inspect Pregel scheduling before considering it an implementation candidate.

### Primary Prior Art And Exact Contract

Primary verification was targeted, not a full paper review. [Jacobi and Goernerup, strong lumpability](https://arxiv.org/pdf/0710.1986), pages 1-2, Theorem 1 and equation (2.1), gives the same class transition formula whenever transitions into each destination class have equal sums for every source member. Identical complete rows are a sufficient special case. Thus closed class-mass iteration is classical lumpability, not a new theorem. The stronger identical-row condition additionally permits one-step vertex reconstruction; arbitrary lumpability does not.

[Francisco et al., Exploiting Computation-Friendly Graph Compression Methods](https://arxiv.org/abs/1708.07271), title/abstract and revision metadata, directly covers adjacency-vector multiplication on compressed representations and PageRank applications. Its reported measurements concern its own workloads, not this design. [Augeri's 2008 dissertation](https://scholar.afit.edu/etd/2632/), repository abstract, is prior work connecting equitable partitions, quotient computation and PageRank. These sources support classifying both row-mass and equal-state quotients as adaptations with a new constrained-lifecycle evaluation, not global novelty. The attempted detailed follow-up fetch of the two-stage PageRank paper timed out; no additional theorem is attributed to that unread portion.

For clarity, one valid restricted contract uses a nonnegative normalized non-dangling transition row `B_g[v]`, zero rows for dangling groups, fixed damping `0 <= d < 1`, normalized teleport vector `p`, and fixed dangling distribution `w`. Let `c(v)` map vertices to exact row classes, `M_t[g]=sum_{c(v)=g} r_t[v]`, `Q[g,h]=sum_{c(v)=h} B_g[v]`, and `p_bar,w_bar` be the corresponding class sums. Let `z_t` be mass in dangling classes. In exact arithmetic:

`M_(t+1) = (1-d)*p_bar + d*(M_t*Q + z_t*w_bar)`

`r_(t+1)[v] = (1-d)*p[v] + d*(sum_g M_t[g]*B_g[v] + z_t*w[v])`.

This is a derivation of the lead's restricted linear contract, not a test rerun. Reconstruct iteration T from iteration T-1 masses; T=0 requires the original initialization. Do not divide masses by cardinality. Identical zero raw rows only remain safely grouped if dangling behavior is also identical. Vertex-dependent damping, customized source-dependent teleportation, weights, filtering, duplicate aggregation or changing initialization require rederiving the operator. Keep `w=p` only when that is the explicit policy.

Two further counterexamples prevent scope inflation. Any stochastic matrix is lumpable into a single class with mass one, yet that scalar cannot recover arbitrary vertex ranks: generic lumpability alone is insufficient for the lift above. Also class totals can conceal within-class changes, so a class residual is not the GDS per-node stopping test. For identical completed rows, a named global L1 residual/error bound can be derived using stochastic contraction; that is a different stopping contract and requires numerical-error allowance. Per-node thresholding must not be commuted through summation.

### Quotient Lifecycle Budget

Use `G` row classes, `L` entries across distinct retained non-dangling rows, and `H` nonzero class-to-class coefficients. With 32-bit IDs and f64 coefficients, a conservative uncompressed supplement is:

`D_extra = 4V + [12L + 8(G+1)] + [12H + 8(G+1)] + teleport/dangling columns + metadata`.

It covers membership, shared rows for reconstruction, and the quotient, not external-ID dictionaries, old generations, original topology retained for other workloads, or build scratch. Uniform vectors may be implicit; arbitrary p and w can cost another `16V` on disk. Rank iteration uses `16G` bytes for two mass vectors plus class teleport/dangling vectors (another `8G` each if distinct), active metadata and buffers. Reconstruction additionally needs a bounded destination tile, its access index or extra scans, and bounded external-ID/result export. A dense f64 quotient at G=100,000 already costs 80GB for coefficients alone, so G much smaller than V does not guarantee the prepared artifact fits.

Import must canonicalize the same filtered, weighted, duplicate-sensitive rows that the algorithm uses. External sort/hash partitioning must charge full-row collision verification, normalization, membership construction, quotient aggregation and destination-tile construction. Hash equality is not proof of row equality. Mathematical equality and bitwise equality of rounded normalized weights are different possible contracts.

First-answer critical path includes that construction plus quotient iterations, full reconstruction and complete export. Iteration traffic includes Q and any spilled class state; reconstruction reads retained B, membership/ID/teleport data and writes V scores. A destination-tile organization can require a transpose of B or repeated scans; neither is free. Compare with the best ordinary streamed kernel from the same raw source, not only an already prepared GDS projection.

Refresh can split a class after one changed edge. Destination class splits may also change Q entries for unchanged source rows, so maintenance is not necessarily proportional to changed edges. Keep stable class identities or charge renumbering. If only class masses were retained, a split cannot generally divide old mass equally; vertex reconstruction is needed before any proposed warm-start reuse, which itself changes finite-iteration semantics unless explicitly permitted. Old and new membership/shared-row/Q extents, rebuild runs, pending changes and reader-pinned exports share the 50GB prepared limit and declared working-disk allowance. This is the most important lifecycle falsifier for the corrected candidate.
